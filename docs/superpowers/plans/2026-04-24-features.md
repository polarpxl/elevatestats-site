## Data shape (`src/lib/features.ts`)

Matches the user's spec with one addition: a `theme` field on each category, driving the section's background and the styling of hero tiles + compact rows inside. Putting this on data (not on the consuming component) keeps the call site in `page.tsx` clean — just `.map(category => <CategorySection category={category} />)`.

Also resolving `href` strings to real `links` values at the data site so the component doesn't need to know about the `links` map.

  id: string
  eyebrow: string
  heading: string
  lede: string
  theme: CategoryTheme
  features: FeatureItem[]
  cta: { label: string; href: string }

export const featureCategories: FeatureCategory[] = [
  {

## Hero tile vs compact row — visual decision

**Hero tile:** `rounded-card` card, icon (circle bg, orange foreground), heading Poppins 600 text-xl, description body text. 2 cards per row on `md`+, 1 on mobile. No Placeholder image per tile — the page already has one big hero placeholder at the top, and adding 10+ more tile placeholders across the page would be visual noise. Text-forward tiles are cleaner and keep the page shippable even without real screenshots.

**Compact row:** small icon at left, `title + short description` stacked on the right. 2 columns on `md`+, 1 on mobile. Smaller type. Subtle top border between items via `divide-y` so the list reads clearly.

**Dark theme variant (Built for the Rink):**
- Section bg: `bg-surface-dark text-white`
- Hero tiles: `bg-white/5 ring-1 ring-white/10` (keeps the card feeling distinct from the section bg), title `text-white`, description `text-white/70`
- Icon circles: `bg-brand-orange/15 text-brand-orange` (orange still reads well on dark; contrast is fine at 15% fill)
- Compact rows: divider `divide-white/10`, title `text-white`, description `text-white/60`
- Lede: `text-white/80`
- Category CTA link: `text-white hover:text-brand-orange` (inverted from the light sections where it's orange-on-white)

Light theme (Live Game Tracking = white, Team & Season Analytics = surface-alt) uses the existing card/row styles from earlier sections for cohesion.

## Icon rotation

Small set of 8 inline SVGs in one file module, keyed by name. `CategorySection` picks an icon for each compact row by cycling through the set (index % icons.length). Hero tiles use a single "highlight" icon per tile — I'll assign them explicitly to make the matching less random. For the 10+ hero tiles across the page, I'll pick a stable icon-per-tile mapping so each hero feature gets a thematically appropriate glyph (shot-on-rink → map-pin, AI Insights → sparkle, offline → wifi-off, etc.).

**Icon set to include (all 24-viewBox, stroke-based, consistent weight 1.8):**
`check`, `sparkle`, `map-pin`, `layers`, `download`, `upload`, `phone`, `wifi-off`, `lightning-bolt`, `chart`, `shield`, `clock`.

For hero tiles (11 total across the three categories), I'll write an explicit `icon` field into the data or match by title heuristically. **Cleanest approach:** extend `FeatureItem` with an optional `icon?: IconName` field that I set only on hero features. Falls back to cycling icons for compact rows. Keeps the mapping explicit, reviewable in one file, and lets you swap icons later without touching the component.

## Decisions flagged

1. **No per-hero-tile Placeholder images.** Each hero tile is icon + heading + description. Rationale above (placeholders everywhere = visual noise). If you'd rather have a thumbnail Placeholder on each hero tile, easy to add — just flag and I'll wire it up with a `placeholderLabel` field on hero features.
2. **Icon mapping on hero features is explicit** via a new `icon?: IconName` field on `FeatureItem`. Compact rows cycle through the icon set by index. Open to changing the mapping if anything reads wrong.
3. **"Built for the Rink" goes fully inverted** (`bg-surface-dark`), not just a tint. Higher contrast, reads as the differentiator. If this feels too heavy next to the other two sections, we can soften to a `bg-[#1a1f26]` mid-tone.
4. **Hero tile grid is 2 columns on md+.** Some categories have 3 hero features (row of 2 + one alone on the second row) and some have 4 (two clean rows of 2). The "Live Game Tracking" category has 4, "Team & Season Analytics" has 4, "Built for the Rink" has 3. The single orphan tile will fill half the row. If it looks lopsided, we can switch to 3 columns on `lg:` for the 3-hero category only — flag once it's built.
