# Elevate Hockey Stats Marketing Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a mobile-first marketing homepage for Elevate Hockey Stats with 9 sections (sticky nav, hero, bento features, how-it-works, use cases, testimonial marquee, CTA panel, blog preview, footer), using brand tokens, Poppins/Plus Jakarta Sans fonts, coloured-box imagery placeholders, and Canadian spelling.

**Architecture:** Single-page App Router route (`src/app/page.tsx`) composed of section components under `src/components/sections/`. Brand tokens live in `globals.css` inside Tailwind v4's `@theme` block as CSS custom properties, producing utility classes like `bg-brand-orange`, `font-heading`, `font-body`. Fonts loaded via `next/font/google` in `layout.tsx` and exposed as CSS variables. Framer Motion used sparingly for the testimonial marquee and subtle hero entrance animations. No new dependencies.

**Tech Stack:** Next.js 16.2.4 (App Router), React 19, TypeScript, Tailwind CSS v4, Framer Motion 12, next/font/google.

## Verified facts (before locking the plan)

- **Tailwind version:** v4 (via `@tailwindcss/postcss` in `postcss.config.mjs` and `@import "tailwindcss"` in `globals.css`). No `tailwind.config.js` exists — v4 is config-in-CSS. Brand tokens go in `@theme` in `globals.css`.
- **Next.js version:** 16.2.4. `next/font/google` still the canonical font loader, attached via `className` on `<html>` as CSS variables.
- **Viewport:** Next 16 expects a separate `export const viewport` in `layout.tsx` (not nested in `metadata`). We'll set `viewportFit: 'cover'` so iPhone notch/home-bar safe-area insets work.
- **Existing `globals.css`** has Geist font variables and a dark-mode block we'll replace.
- **Existing `page.tsx` and `layout.tsx`** are Next's starter boilerplate — we'll overwrite both.
- **`public/`** currently has Next/Vercel SVGs. We'll leave them alone; you'll drop logos into `public/brand/` later (path already assumed in the nav/footer).

## Mobile-first responsive approach

- Base styles target ~375px (iPhone SE / mini). No prefix.
- `md:` (≥768px) for tablet rearrangement — bento grid goes from 1 column to asymmetric multi-column; how-it-works switches from stacked to alternating rows.
- `lg:` (≥1024px) for desktop max-width containers, larger hero type, final layout polish.
- `Container` uses `px-5 md:px-8 lg:px-12` and `max-w-6xl mx-auto`.
- Nav uses `pt-[env(safe-area-inset-top)]` so the iPhone status-bar doesn't overlap. Footer uses `pb-[env(safe-area-inset-bottom)]`.
- Every section gets vertical rhythm via `py-16 md:py-24 lg:py-32`.

```tsx
import { cn } from '@/lib/cn'
import type { ComponentProps, ReactNode } from 'react'

type Variant = 'primary' | 'secondary' | 'ghost'
type Size = 'md' | 'lg'

const base =
  'inline-flex items-center justify-center gap-2 rounded-full font-heading font-semibold transition-colors focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-brand-orange'

const variants: Record<Variant, string> = {
  primary: 'bg-brand-orange text-white hover:bg-[#E65C00]',
  secondary: 'bg-white text-ink ring-1 ring-black/10 hover:bg-surface-alt',
  ghost: 'text-ink hover:bg-black/5',
}

const sizes: Record<Size, string> = {
  md: 'h-11 px-5 text-sm',
  lg: 'h-13 px-7 text-base',
}

export function Button({
  variant = 'primary',
  size = 'md',
  className,
  children,
  ...rest
}: {
  variant?: Variant
  size?: Size
  children: ReactNode
} & ComponentProps<'a'>) {
  return (
    <a className={cn(base, variants[variant], sizes[size], className)} {...rest}>
      {children}
    </a>
  )
}
```
